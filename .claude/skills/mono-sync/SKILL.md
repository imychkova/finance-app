# Синхронізація monobank → застосунок

Дані: офіційне особисте API monobank (https://api.monobank.ua/docs/). Токен і доступ до застосунку лежать у `.env.local` (шаблон `.env.example`). Ніколи не показуй і не коміть токени, не читай `.env.local` у відповідь користувачу.

Особисте API не віддає чеки, лише виписку (`description`, `mcc`, `comment`). Категорії треба підтверджувати з користувачем.

Синхронізується лише гривнева **чорна картка** (`type === 'black'`); інші картки й банки користувача не цікавлять.

## Кроки

1. Перевір, що `.env.local` існує. Якщо ні, попроси користувача створити його за `.env.example` (токен він вставляє сам).
2. Запусти `node tools/mono_fetch.mjs`: за замовчуванням бере останні 31 день (≈ місяць). Якщо користувач чітко назвав дату, з якої синхронізувати, передай `--from YYYY-MM-DD` (довші періоди скрипт ріже на вікна по 31 день). Кожен запит чекає 61 с через ліміт API, тож запускай у фоні й чекай завершення.
3. Запусти `node tools/mono_review.mjs` у фоні та відкрий http://127.0.0.1:8788 (у вбудованому браузері або скажи користувачу відкрити). Сторінка сама знімає дублі (дата + сума ±1 грн з наявними записами), автоматично відкладає внутрішні перекази, банкомати тощо (їх можна повернути галочкою) і пропонує категорії за правилами з `tools/mono_lib.mjs`.
4. Користувач сам у таблиці обирає «Хто» (Я / Yasilda / Разом), категорію й коментар, може змінювати кілька рядків одразу та натискає «Записати». Ти нічого не записуєш без цього натискання.
5. Якщо користувач просить нові правила (напр. «Waikiki → Одяг»), додай їх у `RULES` у `tools/mono_lib.mjs`. Категорії бери лише з тих, що є в застосунку.
6. Альтернатива без інтерфейсу: рішення в `data/mono-decisions.json` (формат у шапці `tools/mono_push.mjs`, є поле `who`) і `node tools/mono_push.mjs data/mono-decisions.json` лише після явного підтвердження користувача. Повторний запуск безпечний: `id` = `mono-<id транзакції>`.

## Правила
- Записуй лише витрати (надходження скрипт відкидає).
- Не змінюй і не видаляй наявні записи в застосунку.
- Файли в `data/` приватні й не потрапляють у git.
